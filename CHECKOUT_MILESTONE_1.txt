POLICIES / SAFETY
Zero payment: booking_status confirmed, paid_amount 0; database payment_status
pending retained for compatibility, presented as Unpaid to the customer.
20%/100%: integer paise computed on server; pending until provider confirms capture.
20% rounds once to nearest paise only if total contains fractional paise after division.
Capture verifies order, payment ID, exact amount, INR and captured=true/status.
Webhook HMAC checked before processing; repeated capture cannot double credit.
Late capture records money without resurrecting cancelled/completed bookings.
Database transaction is designed to insert booking + OTP use + outbox atomically.
Customer ownership uses the existing secure server session and normalized mobile.
Guest booking capability is hashed in DB, stored only in sessionStorage, never in
URLs, and expires for access after seven days. Customer login remains available.
Checkout is gated to testing, an isolated database and matching pricing/storage
configuration. Razorpay live keys are refused by this milestone.
300 km/day, extra-km increment and vehicle allowances remain. Current hardcoded
customer night charge was corrected to read the vehicle's configured night rate,
with the existing Rs500 fallback only if absent. Vendor costing is untouched.
Pickup restriction now matches the explicit Mumbai/Thane/Navi Mumbai instruction;
Maharashtra-wide pickup behavior and its tests were updated. Drops remain nationwide.
Self-drive validation, deposits and document flows were not rewritten.
