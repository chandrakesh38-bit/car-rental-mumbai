APPROVED RULES IMPLEMENTED
Code: CWDLOGIN10. 10% of server-priced eligible fare, capped at INR 500.
Requires the existing OTP-verified customer session and matching booking
mobile identity. A booking OTP alone is not sufficient for coupon use.
Lifetime use is enforced by verified mobile, independent of browser/session.
No stacking rule exists, so stacking is rejected.
The existing with-driver checkout supports local/outstation/airport trips.
Its server fare excludes refundable deposits and unpriced toll/parking
actuals. Self-drive deposits and legacy self-drive pricing are unchanged.

WORKFLOW
- Login invitation remains premium and dismissible, without marketing opt-in.
- Successful OTP login closes it automatically and restores the same results
  and scroll position. An eligible customer gets the code and Copy button.
- Checkout has Coupon Code, Apply and Remove controls. Apply reads a server
  quote and does not consume or reserve the coupon.
- Fare breakdown shows gross fare, coupon deduction and discounted total.
- INR 0 / 20% / 100% options are calculated from the discounted amount.
- Server recomputes pricing at submission. A changed quote is rejected for
  review rather than silently charging a different amount.

CONFIRMATION / CANCELLATION SEMANTICS
The existing checkout confirms INR 0 bookings immediately. The coupon is
redeemed in the same database transaction as that confirmation.
20% and 100% bookings remain received/payment-pending until capture. A coupon
reservation prevents another booking from claiming it meanwhile; there is
no redemption audit entry until the booking is confirmed.
Payment failure or abandonment does not redeem it. The pending booking can
be retried or cancelled using Cancel pending booking, releasing its coupon.
Late capture is recorded but never revives a cancelled booking or redeems its
released coupon. A cancelled discounted booking cannot be re-confirmed after
release. Cancellation after confirmation does not restore lifetime coupon use.
Refund/reconciliation of a late captured payment remains the existing support
workflow; the coupon feature does not initiate refunds.

ATOMICITY / AUDIT
The service-only SQL wrapper checks the session again inside the transaction,
uses the existing checkout lock, computes the capped discount, and creates
the booking and reservation/redemption together. Unique indexes enforce one
active use per mobile and one redemption per mobile and booking.
cwd_login_coupon_uses records reservation/release/confirmation timestamps.
cwd_login_coupon_redemptions records confirmed use, customer, verified mobile,
booking, coupon code, eligible fare and discount. No deletion/update permission
is granted to the API role for the redemption audit. Anonymous/client roles
cannot read these tables or call the coupon RPC. RLS is enabled.
